# 실제 LMS 화면 기반 시연 데이터

`full-demo` 프로필에서 `demo-data/lms_snapshot.json`을 읽어 현재 백엔드 구조에 맞게 입력합니다. 2026-11-10에 로그인된 LMS의 화면을 브라우저로 읽어 정리한 **정적 스냅샷**이며, 매 실행마다 LMS를 크롤링하거나 원본 LMS를 수정하지 않습니다.

## 실행

백엔드 `.env`의 기존 DB 연결·JWT·초기 관리자 설정에 아래 한 줄을 추가합니다. 실제 비밀번호는 Git에 올리지 않습니다.

```properties
app.full-demo.password=본인이_정한_8~72자_시연계정_비밀번호
```

MariaDB를 실행하고 기존 백엔드 서버를 종료한 뒤 백엔드 폴더에서:

```bash
bash scripts/seed-demo.sh mariadb
```

H2를 사용할 때는 `bash scripts/seed-demo.sh local`을 실행합니다. Windows PowerShell에서는 다음과 같습니다.

```powershell
.\gradlew.bat bootRun --args='--spring.profiles.active=mariadb,full-demo'
```

`[full-demo] Complete: cohort=... snapshot=2026-11-10`이면 완료입니다. 입력 후 서버는 계속 실행됩니다. 공유 DB는 한 명만 입력하면 되고 개인 DB는 각자 실행합니다. 서버 시작 시점의 `.env`에 연결된 DB를 사용합니다.

## 입력 내용

| 구분 | 기본 입력 |
| --- | --- |
| 과정·기수 | 실제 과정명, 기간 2026-07-24~2027-01-27, 총 960시간. 구분용 기수명은 `AM Inspire Camp 6기 (LMS 기반 시연 v2)` |
| 교육 일정 | 11월 목록의 프로젝트·해커톤·특강·멘토링 7개 + 로드맵에서 확인한 전체 휴강일 19개 = 26개 |
| 과정 공지 | 실제 제목·작성일 21개. 264·262·140번은 본문 요약, 나머지는 본문 미수집 표시와 원문 링크 |
| 과제 | 실제 과제 `0917` 1개. 본문 `0917`, 등록 2026-09-17 06:34, 마감 2026-09-20 15:34(KST). 원본 ZIP 미등록 |
| 평가 | 실제 목록의 1·2차 사전/사후 평가 4개와 기간·영역. 문제·정답·응시 기록은 미수집이므로 생성하지 않음 |
| 강의 | 기존 저장소 TSV에 있는 실제 강의 230개를 재사용 |
| 계정 | 가상 학생 2명·강사 1명·기수 매니저 1명. 관리자 계정은 기존 bootstrap 설정 |
| 출결 | 실제 교육 기간·주말·확인된 휴강일 기준 67일에 **가상 출석 65일·지각 1일·결석 1일**. 실제 학생 출결을 복사하거나 수정하지 않음 |
| 소명 | 위 가상 출결의 대기 2건, 승인·반려·무효화 각 1건. 대기 소명을 관리자가 직접 처리 가능 |
| 알림 | 가상 학생 안내 3개. 실제 개인 알림은 가져오지 않음 |

로드맵 5단계·과목 목록과 스터디 2개의 비개인 메타데이터도 참고 파일에 보관했습니다. 최신 develop의 V5에서 해당 기능·테이블이 제외되었으므로 DB에는 입력하지 않습니다. 삭제된 API나 테이블을 다시 만들지 않습니다.

평가 설명에는 원본 문항 수(60/80)를 참고로 남기지만 실제 등록된 문항은 0개입니다. 목록 메타데이터만으로 문제·정답을 만들어 넣지 않습니다. 원본 문제 시연은 팀의 평가 JSON 사본을 사용하는 기존 [demo-seed](DEMO_SEED.md) 가이드를 참고하세요. 이 프로필과 `demo-seed`는 별도 기수에 입력되므로 함께 지정하지 마세요.

## 시연 계정

| 역할 | 이메일 |
| --- | --- |
| 대표 학생 | `student@full-demo.test` |
| 동료 학생 | `peer@full-demo.test` |
| 강사 | `instructor@full-demo.test` |
| 기수 매니저 | `manager@full-demo.test` (전역 STUDENT, 기수 MANAGER) |
| 관리자 | `.env`의 `BOOTSTRAP_ADMIN_EMAIL` |

가상 4계정의 초기 비밀번호는 `app.full-demo.password`입니다. 기존 계정은 역할·ACTIVE 상태가 맞으면 재사용하며 비밀번호를 덮어쓰지 않습니다. 출결 관리는 ADMIN 전용입니다.

## 수집과 변환 기준

- 출처: https://lms.wsts.kr/ 의 `/schedule`, `/roadmap`, `/dashboard`, `/assignment`, `/evaluation/list`, `/studyGroup/` 화면.
- 수집은 로그인된 사용자에게 보이는 화면에서만 수행했습니다. 쿠키·인증 토큰·숨겨진 내부 API·원본 DB는 추출하지 않았습니다.
- 원문 작성자·수강생 이름·연락처·개인 성적·출결·소명·과제 제출물은 수집 파일에서 제외했습니다.
- 게시글 원문 작성자는 복제하지 않고 시연 관리자에게 연결합니다. 조회 수·원본 파일·미확인 본문을 만들지 않습니다. 원본 작성 시각은 날짜만 확인하여 한국 날짜 자정으로 정규화했습니다.
- 일정에 시각이 없는 경우 KST 시작일 00:00부터 종료일 다음날 00:00까지의 날짜 범위로 저장합니다. 이는 저장 규칙이며 실제 강의 시작 시각을 뜻하지 않습니다. 장소는 미확인이라 빈 값입니다.
- 과제 화면 표시 시각은 KST로 보고 UTC로 변환합니다. 원본 파일명 `react_0917.zip`, `spring_0917.zip`은 참고 목록에만 남기고 가짜 다운로드 파일을 만들지 않습니다.
- 평가의 개인 점수·평균 점수는 보관하지 않습니다. Discord Webhook도 호출하지 않습니다.
- 휴강일은 해당 LMS 로드맵 표시를 따르며 법정 공휴일 전체를 별도로 추정하지 않았습니다.
- 실제 화면의 총시간(960)과 표시된 단계 합계(944)는 그대로 보존합니다. 원본 숫자를 맞추려고 임의 변경하지 않았습니다.

## 선택: 가상 기능 시나리오 추가

실제 과제는 마감 상태이고 평가 문제는 미수집입니다. 제출·채점·평가 풀이·복습 연결까지 시연해야 한다면 **최초 실행 전** 다음 옵션을 추가할 수 있습니다. 기본값은 false입니다.

```properties
app.full-demo.synthetic-scenarios=true
```

이 경우 별도 가상 과제 3개(미제출·제출·92점 채점), 합성 4지선다 평가 2개·가상 50점 결과, 실제 다운로드 가능한 가상 답안 텍스트 2개, 가상 학습 분류·예시 영상 연결을 추가합니다. 과제와 평가에 시연 표시를 붙이며 원본 LMS 데이터로 취급하지 않습니다. 영상과 합성 문제의 내용 일치·시작 시각은 검증하지 않았습니다.

## 재실행

같은 v2 기수가 있으면 전체 입력을 건너뛰어 승인·채점 진행 결과를 보존합니다. 비밀번호·옵션·파일을 바꿔도 이미 생성된 기수에 덮어쓰지 않습니다. 기존 v1 시연 기수나 다른 팀원의 데이터도 삭제하지 않습니다. 초기 상태가 필요하면 별도 빈 DB를 사용하세요.

## 검증 범위

신규 통합 테스트는 기본 수집 모드의 실제 제목·기간·건수·기본 가상 시나리오 비활성화, 출결 65/1/1, UTC 날짜 범위, 원본 과제 기한, 선택 시나리오의 조회·첨부 다운로드·소명 승인, 재실행 중복 방지를 검사합니다. 이번 변경의 실제 MariaDB·프론트 화면·YouTube 재생·Discord 전송 결과는 별도로 확인하기 전까지 미검증입니다.

최종 검증: `SPRING_PROFILES_ACTIVE=test ./gradlew build --no-daemon --max-workers=1 --no-watch-fs` 성공. 전체 테스트 72개(신규 3개 포함), 실패·오류·건너뜀 0. `bash -n scripts/seed-demo.sh`와 `git diff --check` 통과. 이번 v2 변경은 H2 통합 테스트로 검증했으며 MariaDB 실행 검증은 재수행하지 않았습니다.
