# 전체 기능 시연 데이터

`full-demo` 프로필에서만 동작하는 합성 데이터 시드입니다. 서버 시작 시 한 번 입력하고 서버는 계속 실행됩니다. 기존 Flyway·일반 실행·프론트 소스를 변경하지 않습니다.

## 팀원에게 전달할 실행 방법

최신 develop(이 PR 병합 이후)을 받고 저장소 루트 `.env`에 다음 설정을 준비합니다. 비밀번호와 JWT는 각 환경에서 정하며 Git·채팅에 원문을 올리지 않습니다.

```properties
# 기존 DB_URL, DB_USERNAME, DB_PASSWORD, JWT_SECRET 설정은 그대로 사용
BOOTSTRAP_ADMIN_EMAIL=admin@your-demo.test
BOOTSTRAP_ADMIN_PASSWORD=본인이_정한_8자_이상_비밀번호
app.full-demo.password=본인이_정한_8~72자_시연계정_비밀번호
# 선택: 출결·일정·로드맵 기준 월 (기본 2026-11)
app.full-demo.month=2026-11
```

관리자 이메일은 사용 가능한 관리자 계정으로 설정합니다. 존재하는 관리자는 비밀번호를 재설정하지 않으므로 기존 비밀번호로 로그인합니다. `.env`의 키만 추가하고 기존 DB 설정을 덮어쓰지 마세요.

MariaDB가 실행된 상태에서:

```bash
bash scripts/seed-demo.sh mariadb
```

Docker가 없는 로컬 H2 시연:

```bash
bash scripts/seed-demo.sh local
```

Windows PowerShell 또는 스크립트 대신 직접 실행:

```powershell
.\gradlew.bat bootRun --args='--spring.profiles.active=mariadb,full-demo'
```

로그의 `[full-demo] Complete: cohort=... month=...`가 생성 완료 표시입니다. 이후 `full-demo` 프로필 없이 일반 실행해도 데이터는 남습니다. 이미 같은 시연 기수가 있으면 입력을 건너뛰고 서버를 실행합니다. 기본 포트는 8080이며 기존 서버가 있으면 먼저 종료하거나 SERVER_PORT를 바꾸세요. DB의 기존 사용자·기수·학습 기록은 삭제하지 않습니다.

## 계정·기수

| 항목 | 값 |
| --- | --- |
| 기수 | `AM Inspire Camp 6기 (전체 시연 v1)` |
| 관리자 | `.env`의 `BOOTSTRAP_ADMIN_EMAIL` |
| 대표 학생 | `student@full-demo.test` |
| 동료 학생 | `peer@full-demo.test` |
| 강사 | `instructor@full-demo.test` |
| 기수 매니저 | `manager@full-demo.test` (전역 STUDENT, 기수 MANAGER) |
| 위 4계정 초기 비밀번호 | `.env`의 `app.full-demo.password` |

로그에 나온 기수 ID 또는 `GET /api/cohorts`의 해당 이름으로 연결합니다. 고정 ID를 가정하지 않습니다. 기존 동일 이메일 계정은 ACTIVE·역할이 일치할 때만 재사용하고 비밀번호는 바꾸지 않습니다. 출결·소명 관리 권한은 ADMIN만 허용됩니다.

## 들어가는 데이터와 시연 순서

| 기능 | 내용 |
| --- | --- |
| 대시보드·계정 | 과정 1개, 기수 1개, 학생 2명·강사·매니저 수강 등록 |
| 캘린더·로드맵 | 기준 월 9~13일 강의·프로젝트·특강·휴강 5개, 단계 1개·모듈 2개 |
| 출결 | 대표 학생의 1~9일 일자 기록 9개, 9일 회차 기록 2개. 출석·지각·결석·공결·휴가·조퇴 모두 포함, 입퇴실 UTC 저장 |
| 소명 | 승인 대기 2개, 승인·반려·무효화 각 1개. 승인 대기를 직접 처리하거나 다른 결석 기록에서 새 소명 제출 가능 |
| 게시판 | COURSE·SYSTEM·ATTENDANCE·QUESTION·FAQ 각 1개, 질문 댓글 1개, 공지 실제 텍스트 첨부 1개 |
| 과제 | 미제출·제출 완료·채점 완료 3개, 제출물 2개와 텍스트 첨부 2개, 채점 피드백 1개 |
| 평가 | 응시 가능한 PUBLISHED 평가와 종료된 CLOSED 평가 각 1개, 각각 합성 4지선다 2문항 |
| 결과·복습 연결 | 대표 학생 종료 평가 50점, 문항별 학습 주제·소단원 연결, 오답 복습 추천 조회 가능 |
| 영상·커리큘럼 | 저장소 TSV의 기존 강의 230개, 과목·단원·주제·소단원 각 1개 |
| 스터디·알림 | OPEN 스터디 1개(멤버 2명), 대표 학생 미확인 알림 3개 |

학생 로그인 → 전체 시연 기수 선택 → `2026-11` 캘린더·출결 확인 → 관리자 로그인하여 대기 소명 승인 → 학생 재조회로 출석 변경 확인 순으로 시연할 수 있습니다. 과제 제출·관리자 채점, 응시 가능한 평가 풀이, 종료 평가 결과·오답 복습, 게시글 댓글·첨부 다운로드도 별도로 시연할 수 있습니다.

평가 창은 **최초 실행 시각 전날부터 7일 후까지**이며 재실행으로 늘어나지 않습니다. 기준 월 설정은 일정·출결·로드맵에 적용되고 기존 강의 날짜는 2026년 7~10월 그대로입니다. 해당 월의 다시보기는 7~10월로 이동하여 확인합니다.

## 기존 강의·평가 전용 시드와의 관계

- `demo-seed`는 팀원의 실제 평가 JSON 사본·검증한 복습 연결을 이용하는 별도 프로필입니다. 기존 구현을 그대로 유지합니다.
- `full-demo`는 비공개 평가 JSON이 없어도 실행되며 독립된 기수·학생 이메일을 사용합니다. 실행할 때 `demo-seed`를 함께 지정하지 마세요.
- 합성 평가의 정답·해설은 직접 작성했습니다. 영상 연결은 **API 흐름을 보여주기 위한 예시**이며 첫 영상 0초의 실제 강의 내용과 평가 개념이 일치한다고 검증하지 않았습니다. 실제 문항·내용에 맞는 연결 시연은 기존 `demo-seed`를 사용하세요.
- 실제 파일 업로드 예시는 텍스트 파일입니다. 저장소 경로에 원본을 생성하고 DB와 함께 보관해야 다운로드가 됩니다. 입력 실패 시 트랜잭션을 롤백하고 이번에 만든 첨부도 정리합니다.
- Discord는 전송 이력을 조작하지 않고 Webhook도 호출하지 않습니다. 게시글의 실제 전송 버튼으로 별도 시연합니다.
- 제외된 AI 백지 복습·객관식 복습 기능 데이터는 넣지 않습니다. 기존에 없는 기능이나 외부 서비스의 정상 동작을 만들어내지 않습니다.

## 재실행·초기화

동일 기수 이름이 있으면 전체 입력을 건너뜁니다. 승인·채점 등 시연 진행 결과를 보존하며 부분 추가·복구·초기화 기능은 없습니다. 기준 월·비밀번호를 바꿔도 이미 만들어진 데이터에는 반영되지 않습니다. 공유 DB를 지워 재실행하지 마세요. 처음부터 확인하려면 별도의 빈 DB를 준비하고 DB_URL을 해당 DB로 바꿉니다.

## 검증

- H2(MariaDB 호환 모드) 통합 테스트에서 자동 입력, 계정 로그인, 주요 학생 조회 API, 종료 평가 복습 추천, 실제 첨부 다운로드, 관리자 소명 승인, 재실행 중복 방지를 검사합니다.
- `SPRING_PROFILES_ACTIVE=test ./gradlew clean build --no-daemon --max-workers=1 --no-watch-fs`: 전체 60개 테스트 통과(신규 2개 포함).
- 격리된 MariaDB 13.0.2의 새 DB에서 mariadb,full-demo 프로필로 실행하여 Flyway V1/V2/V3 적용·전체 시드 완료 및 주요 테이블 건수를 확인했습니다. 프로젝트 기준 MariaDB 11.8과 실제 프론트 화면·YouTube 재생 내용·Discord 전송은 검증하지 않았습니다.
