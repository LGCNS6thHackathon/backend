# ADMIN·STUDENT 역할 통합

백엔드의 권한은 `users.role`을 기준으로 `ADMIN`(관리자), `STUDENT`(학생)만 사용합니다. 강사·매니저는 별도 권한이 아닙니다. 프론트 코드는 이번 작업에서 변경하지 않았습니다.

## API 사용 규칙

- ADMIN은 기수 배정 없이 모든 기수의 계정·과정·출결·게시판·과제·평가·일정·영상·Discord 관리 기능을 사용합니다.
- STUDENT는 배정된 기수의 자료와 본인 제출물·출결·소명·평가 결과에 접근합니다. 기존 본인 게시글·댓글 수정 권한은 유지합니다.
- `POST /api/users`는 STUDENT 계정을 발급합니다. 관리자 지정은 `PATCH /api/users/{userId}`에 `{"role":"ADMIN"}`을 전달합니다. 학생으로 변경할 때는 `STUDENT`를 사용합니다.
- 기수 등록·수정의 `role`은 호환성을 위해 유지합니다. 생략하면 계정 역할을 따르고, 지정하면 계정 역할과 같아야 합니다. 다른 역할을 지정하면 400입니다. 이 필드만 ADMIN으로 바꿔도 관리 권한이 생기지 않습니다.
- 계정 역할 변경 시 모든 기수 등록의 역할도 갱신합니다. 기존 접근·갱신 토큰을 무효화하므로 다시 로그인해야 합니다. 마지막 활성 관리자를 해제하는 기존 제한도 유지합니다.
- 역할 변경·기수 등록 API는 `INSTRUCTOR`, `MANAGER` 값을 받지 않습니다. 신규 기능 및 데모 데이터도 ADMIN/STUDENT만 사용하세요.
- 과제의 `instructorId`, `instructorName` 필드명과 강사 표시 이름은 유지합니다. 연결할 `instructorId`는 활성 ADMIN 계정이어야 하며 해당 기수 등록은 필수가 아닙니다. 점수·평가는 ADMIN만 등록·수정합니다.

## 기존 DB 이관

다음 백엔드 시작 시 Flyway V6가 적용됩니다. 기존 V1~V5 파일은 변경하지 않습니다.

| 기존 데이터 | V6 적용 결과 |
| --- | --- |
| 전역 INSTRUCTOR 계정 | ADMIN |
| 전역 STUDENT이면서 ACTIVE 기수 등록에 INSTRUCTOR 또는 MANAGER가 있는 계정 | ADMIN |
| WITHDRAWN 기수 등록에만 관리 역할이 있는 STUDENT | STUDENT 유지 |
| 기존 ADMIN 또는 일반 STUDENT | 기존 계정 역할 유지 |
| 모든 기수 등록의 role | 변경 후 계정 역할과 동일하게 정리 |

이관으로 역할이 바뀐 계정의 `token_version`을 증가시키고 갱신 토큰을 폐기합니다. 해당 사용자는 다시 로그인해야 합니다. 비활성 계정은 DISABLED 상태를 유지하며 계정 ID·비밀번호·과제 담당자·제출물·평가 이력은 보존합니다. 이후 DB 제약도 ADMIN/STUDENT만 허용합니다.

ERD Cloud 파일은 [erd/lms.erdcloud.json](erd/lms.erdcloud.json), API 계약은 [API_SPEC.md](API_SPEC.md), 전체 스키마는 [erd/lms-mariadb.sql](erd/lms-mariadb.sql)에 반영되어 있습니다.
