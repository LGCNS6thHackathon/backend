# 출결·소명 실제 서버 검증

## 목적

관리자 출결 기록관리·소명 요청 확인·정정 허용, 학생 일정/출결 캘린더의 흐름을 실제 HTTP와 DB로 검증한다. 기존 구현을 재사용하며 프론트 코드는 변경하지 않는다.

## 실행

별도의 일회용 로컬 DB에 백엔드를 `mariadb` 프로필로 실행한 뒤 관리자 계정 정보를 환경 변수로 전달한다. 스크립트는 로컬 주소만 허용하고 리다이렉트를 따르지 않는다. 그래도 실제 로컬 업무 서버를 구분해 주지는 않으므로 반드시 일회용 DB를 사용한다.

```bash
export ATTENDANCE_ADMIN_EMAIL='검증 서버의 관리자 이메일'
export ATTENDANCE_ADMIN_PASSWORD='검증 서버의 관리자 비밀번호'
node scripts/verify-attendance.mjs http://127.0.0.1:18081
```

비밀번호·JWT는 파일이나 로그에 저장하지 않는다. 계정·과정·기수·출결·소명·알림 합성 데이터가 생성되며 삭제하지 않는다. 실행마다 새 계정을 발급한다. 재실행 또는 수동 확인이 끝나면 검증 서버와 임시 DB를 정리한다.

## 검증 항목

1. 관리자 회차 출결 생성
2. 학생 캘린더 본인 출결·정정 목표 조회
3. 타인 출결 미노출 (추가로 무인증 401, 잘못된 월 400, 타인 소명 403 확인)
4. 소명 대기 시 재요청 차단·캘린더 목표 상태 비활성화
5. 학생의 출결 관리·소명 승인 403, 폐지된 INSTRUCTOR/MANAGER 역할 지정 400
6. 소명 목록의 본인 접근 범위
7. 관리자 승인 후 학생 캘린더의 출결·소명 상태 갱신
8. 이미 처리된 요청 재승인 409
9. 반려 후 재신청 가능 상태
10. 원본 수정 시 소명 무효화
11. 원본 삭제 시 캘린더에서 제외
12. 삭제 후에도 관리자 소명 이력의 INVALIDATED 확인
13. 여섯 정정 전환의 승인 처리 및 직접 수정 우회 차단
14. 일자·회차 출결 공존
15. 기수 교육일정의 캘린더 반영
16. 다른 기수 캘린더 접근 차단

## 2026-11-10 실행 결과

- 격리된 MariaDB **13.0.2**를 임시 폴더에서 실행했다. Docker 데몬이 실행 중이 아니어서 설치된 로컬 MariaDB를 사용했다.
- 프로젝트 compose 기준 **11.8과 버전이 다르다**. 이 결과를 11.8 검증으로 간주하지 않는다.
- 기존 전역 MySQL 설정의 mysqlx-bind-address가 초기화를 방해했다. `--no-defaults`로 임시 인스턴스가 시스템 설정을 읽지 않게 하여 해결했다. 전역 설정은 수정하지 않았다.
- 새 검증 DB에 Flyway V1·V2·V3 적용 성공. 백엔드 `mariadb` 프로필 기동 성공.
- 위 **16개 검증 흐름 모두 통과**. 스크립트가 실패하면 assertion과 실패한 요청 경로·상태를 출력하고 종료 코드가 0이 아니게 된다.
- 기존 사용자 DB와 프론트 코드는 수정하지 않았다. 브라우저 UI는 검증하지 않았다.

- `./gradlew clean build --no-watch-fs` 성공. 전체 테스트 **39개 통과**(실패·오류·건너뜀 0). 첫 build는 기존 중복 ` 2.class` 산출물 때문에 실패했으며 clean 재빌드로 해결했다. `node --check`와 `git diff --check` 통과. 검증용 서버·DB와 임시 자격 증명은 모두 정리했다.

## 2026-11-10 입퇴실 시간 보완 후 추가 검증

PR #15가 병합된 최신 develop(7715229)을 기준으로 격리된 MariaDB 13.0.2와 백엔드 mariadb 프로필에서 스크립트를 다시 실행했다. 기존 16개와 아래 6개, 총 **22개 검증 흐름 모두 통과**했다.

17. 캘린더에서 실제 입실·퇴실 시각의 UTC 반환
18. 시간 없이 메모만 수정해도 기존 입퇴실 보존
19. 입실이 퇴실보다 늦음·입실만 null 삭제·시각이 남은 결석 변경을 400으로 거부하고 원본 상태·시각·버전 유지
20. 퇴실만 수정하면 입실은 보존
21. 퇴실을 명시적 null로 지우면 입실은 보존
22. 입퇴실 모두 명시적 null로 지운 결석 기록은 캘린더에도 두 키를 null로 반환

`node --check scripts/verify-attendance.mjs`, `git diff --check` 통과. 이번 변경은 검증 스크립트·문서만이며 전체 JUnit 빌드를 재실행하지 않았다. 기능 코드의 선행 PR에서 전체 43개 테스트가 통과한 기록과 구분한다. MariaDB 11.8 및 실제 프론트 UI는 미검증이다.
